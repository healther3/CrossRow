# CrossRow 多智能体系统评分标准

## 概述

本文档定义了 CrossRow 多智能体系统的评估框架，用于衡量系统在路由准确性、响应质量和系统稳定性三个维度的表现。

---

## 一、路由准确性评分 (40%)

Router 负责将用户问题分发到正确的专家 Agent，是系统的核心组件。

### 1.1 哲学领域识别 (10%)

| 问题类型 | 示例 | 期望路由 |
|---------|------|---------|
| 存在主义 | "生活的意义是什么？" | philosophy |
| 伦理学 | "我应该追求快乐还是意义？" | philosophy |
| 形而上学 | "人死后会怎样？" | philosophy |
| 荒诞主义 | "西西弗斯的神话告诉我们什么？" | philosophy |
| 东方哲学 | "道家思想如何看待人生？" | philosophy |

### 1.2 心理学领域识别 (10%)

| 问题类型 | 示例 | 期望路由 |
|---------|------|---------|
| 焦虑症状 | "我最近总是失眠，很焦虑" | psychology |
| 自我价值 | "我感觉自己一无是处" | psychology |
| 情绪调节 | "我无法控制自己的情绪" | psychology |
| 行为模式 | "我总是拖延，怎么办？" | psychology |
| 人际关系 | "我和父母的关系很紧张" | psychology |

### 1.3 社会学领域识别 (10%)

| 问题类型 | 示例 | 期望路由 |
|---------|------|---------|
| 社会经济 | "为什么房价这么高？" | sociology |
| 职场文化 | "职场内卷太严重了" | sociology |
| 消费主义 | "为什么大家都在追求物质？" | sociology |
| 社会分层 | "阶层固化是真的吗？" | sociology |
| 社会现象 | "为什么年轻人不想结婚？" | sociology |

### 1.4 边界问题处理 (10%)

边界问题是指可能涉及多个领域的复杂问题。评估标准：

- **优秀**: 路由到最根本的问题领域
- **良好**: 路由到合理的相关领域
- **及格**: 路由到三个领域之一
- **不及格**: 无法路由或返回无效结果

| 问题 | 可接受路由 | 最佳路由 |
|-----|-----------|---------|
| "我考试失败了，感觉人生没有意义" | psychology/philosophy | psychology |
| "996工作制让我很抑郁" | psychology/sociology | psychology |
| "为什么努力没有回报？" | philosophy/sociology | philosophy |

## 二、响应质量评分 (50%)

### 2.1 相关性 (Relevance) - 20%

| 分数 | 标准 |
|-----|------|
| 18-20 | 完全切题，直接回应用户核心诉求 |
| 14-17 | 基本切题，覆盖主要问题 |
| 10-13 | 部分相关，但有偏离 |
| 5-9 | 相关性较低 |
| 0-4 | 完全不相关 |

### 2.2 专业性 (Professionalism) - 15%

| 分数 | 标准 |
|-----|------|
| 13-15 | 引用具体理论/学派，提供深度分析 |
| 10-12 | 使用领域术语，有理论支撑 |
| 7-9 | 有一定专业性，但深度不足 |
| 4-6 | 专业性较弱 |
| 0-3 | 无专业内容 |

**各领域专业性指标：**

- **哲学**: 引用哲学家观点、学派理论（如存在主义、斯多葛主义）
- **心理学**: 使用心理学概念（如认知行为、防御机制）、提供实用建议
- **社会学**: 分析社会结构、引用社会学理论（如马克思主义、功能主义）

### 2.3 完整性 (Completeness) - 15%

| 分数 | 标准 |
|-----|------|
| 13-15 | 提供完整分析 + 多角度建议 + 后续指导 |
| 10-12 | 分析较完整，有具体建议 |
| 7-9 | 基本完整，但缺少某些方面 |
| 4-6 | 不够完整 |
| 0-3 | 严重不完整 |

### 2.4 清晰度 (Clarity) - 15%

| 分数 | 标准 |
|-----|------|
| 13-15 | 结构清晰，逻辑严密，易于理解 |
| 10-12 | 表达清楚，结构合理 |
| 7-9 | 基本清楚，但有些混乱 |
| 4-6 | 表达不够清晰 |
| 0-3 | 混乱难懂 |

### 2.5 共情度 (Empathy) - 15%

| 分数 | 标准 |
|-----|------|
| 13-15 | 充分理解用户情感，回应温暖有力 |
| 10-12 | 体现对用户的理解和关心 |
| 7-9 | 有一定共情，但不够深入 |
| 4-6 | 共情不足 |
| 0-3 | 冷漠或机械 |

**注**: 心理学领域问题的共情度权重应适当提高。

## 三、系统稳定性评分 (10%)

### 3.1 SSE 流稳定性 (5%)

| 分数 | 标准 |
|-----|------|
| 5 | 流式输出稳定，无中断，响应时间合理 |
| 3-4 | 偶有延迟，但能正常完成 |
| 1-2 | 有中断或超时 |
| 0 | 无法正常输出 |

### 3.2 错误处理 (5%)

| 分数 | 标准 |
|-----|------|
| 5 | 异常情况优雅降级，有兜底方案 |
| 3-4 | 能处理大部分异常 |
| 1-2 | 部分异常未处理 |
| 0 | 异常导致系统崩溃 |

---

## 四、综合评分等级

| 等级 | 分数范围 | 说明 |
|-----|---------|------|
| **优秀 (A)** | 90-100% | 系统表现出色，可投入生产使用 |
| **良好 (B)** | 80-89% | 系统表现良好，需少量优化 |
| **及格 (C)** | 60-79% | 系统基本可用，需要改进 |
| **不及格 (D)** | <60% | 系统存在严重问题，需要重构 |

## 五、AskHuman 工具调用评估 (附加维度)

### 5.0 AskHuman 调用意识评分

评估 Agent 是否能在适当时机主动询问用户澄清，而不是盲目猜测。

#### 5.0.1 应该调用 AskHuman 的场景

| 场景类型 | 示例输入 | 期望行为 |
|---------|---------|---------|
| 缺少关键信息 | "帮我搜一下" | 询问搜索主题 |
| 指代不明 | "那个问题怎么解决" | 询问具体指代 |
| 多义请求 | "生成一张图" | 询问图片内容 |
| 模糊目标 | "帮我处理一下" | 询问处理对象 |
| 缺少上下文 | "继续" (无前文) | 询问要继续什么 |

#### 5.0.2 不应该调用 AskHuman 的场景

| 场景类型 | 示例输入 | 期望行为 |
|---------|---------|---------|
| 明确请求 | "搜索2024诺贝尔奖得主" | 直接执行搜索 |
| 完整描述 | "生成赛博朋克风格城市图" | 直接生成图片 |
| 哲学讨论 | "人生的意义是什么" | 直接进行哲学对话 |

#### 5.0.3 评分标准

| 分数 | 标准 |
|-----|------|
| 5 | 100% 正确判断何时询问、何时执行 |
| 4 | 90%+ 正确，偶有过度询问 |
| 3 | 70%+ 正确，有时猜测用户意图 |
| 2 | 50%+ 正确，经常猜测或过度询问 |
| 1 | 几乎不使用 AskHuman 或滥用 |

## 六、持续改进建议

### 5.1 路由测试用例

1. **典型问题**: 每个领域 5-10 个典型问题
2. **边界问题**: 涉及多领域的复杂问题
3. **干扰问题**: 包含误导性关键词的问题
4. **简短问题**: 信息量少的问题
5. **长文问题**: 包含大量背景信息的问题

### 5.2 响应质量测试用例

1. **深度问题**: 需要专业知识的问题
2. **情感问题**: 需要共情的问题
3. **实用问题**: 需要具体建议的问题
4. **理论问题**: 需要学术分析的问题

---

## 六、持续改进建议

### 7.1 数据收集

- 记录所有路由决策和用户反馈
- 收集响应质量的人工评分
- 监控系统性能指标

### 7.2 模型优化

- 根据错误案例调整 Router Prompt
- 优化各领域 Expert Agent 的系统提示
- 扩充 RAG 知识库

### 7.3 评分标准迭代

- 定期审查评分标准的合理性
- 根据实际使用情况调整权重
- 增加新的评估维度
